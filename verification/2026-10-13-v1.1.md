## 实机排障（0.2.0 首次重装后整页消失，2026-10-13）

证据链（真实命令输出摘要）：

1. 桌面端 profile：`%APPDATA%\dsh-desktop\harness\profiles\web`，插件经 junction 指向 generation `local+dsh-token-plan-dashboard+0.2.0+84ce48fcb771`，磁盘代码确为 0.2.0。
2. **运行中宿主仍是旧代码**：`Invoke-WebRequest http://127.0.0.1:43129/dsh-token-plan-dashboard/state` 返回 200 但 providers **无 `enabled` 字段**（0.1.0 形状）→ 重装不触发 host 重载，需重启应用。
3. **bundle dependencies 不落盘**：generation 的 `.pnpm/lock.yaml` 与 `.modules.yaml` 均记录 `@deepseek-ai/schemastery@3.18.4`（hoisted），但 `node_modules/@deepseek-ai/` 为空目录；从插件目录实测 `import('@deepseek-ai/schemastery')` → `RESOLVE FAIL: Cannot find package`。
4. 应用自带副本可用：`D:\DeepSeek\DSH Desktop\resources\app.asar.unpacked\node_modules\@deepseek-ai\schemastery`（3.18.4，与官方插件同源），ESM 入口 `lib/index.mjs`。

根因结论：① client 硬 inject configForms 导致整个 client 插件不激活（页面全灭）；② schemastery 裸 import 必失败（安装器不落实 dependencies）。修复（0.2.1）：client 改运行时探测 + 降级；host 改解析链兜底。

## 三次排障（0.2.2 实机：configForms 服务未注入，2026-10-13）

证据链：

1. `/state` 探测：`configActive: true`、三家 `enabled: true` → 0.2.2 host 侧 Config 已激活（解析链在真实 host 进程命中）。
2. 设置区新警告文案为「configForms 服务未注入」（`missing` 分支）→ client 侧 `ctx.configForms` 探测为 null，即 cordis 对未声明服务不可见。
3. `resources/app.asar.unpacked/node_modules/@deepseek-ai/dsh-web-app/cordis.patch.yml` 含 `- id: ui-settings / name: '@deepseek-ai/dsh-client-ui-settings'` → configForms 服务在组合中存在，可正常服务级 inject。
4. 复盘 0.2.0 整页死亡真因：当时同时改了服务级 inject 与包级 `dsh.client.inject` 两个变量；profile `package.json` 依赖树只有四个 bundle，不含 ui-settings 包 → 包级注入解析失败杀死整个 client 插件。服务级 inject 是无辜的。

修复（0.2.3）：client.js 服务级 inject 恢复 `'configForms'`，包级 `dsh.client.inject` 维持不含该包。复检：`node --check` × 2 + 冒烟 SMOKE OK。
